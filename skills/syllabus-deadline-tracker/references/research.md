# Researching an exam or goal from just its name

Use this when the user names an exam, certification, course or goal (for example "SSC CGL tier 1", "UPSC prelims", "AWS Solutions Architect", "semester 5 finals") instead of supplying a syllabus. Any exam or deadline is in scope; the research is what makes the plan accurate.

## 1. Pin down exactly what the target is
Exams often have stages, posts, groups, papers or shifts, and the user's phrase may fit more than one (for example prelims versus mains, or two different posts or papers, which can have different patterns and dates). If the sources show several candidates, pick the one with a confirmed date and state the assumption in the reply and in the config `notes`. Ask the user only when the choice changes the plan materially and you cannot infer it.

## 2. Collect facts, with sources
Search the web and fetch the pages (do not rely on memory; dates and patterns change yearly). Find, in this order of trust:
1. The conducting body's official notice, syllabus rules or notification (board or commission website, official recruitment portal).
2. Official schedules and calendars (exam calendar, admit-card notices).
3. Reputable aggregators that quote the official notice and link it.
4. Coaching sites and blogs: useful for explanation, never as the only source for dates or marks.
Extract: stage structure, dates (confirmed vs tentative), papers with marks, duration, language or medium, negative marking, question types (objective or descriptive), syllabus by paper and section, and marks per section where given. Note conflicts between sources and resolve them in favour of the official one; if you cannot, mark the date tentative and tell the user.

Check the user's own position too: for multi-stage exams, ask or note whether an earlier stage is passed, pending or results are out, since it changes urgency.

## 3. Turn the pattern into a plan
- Weight study time by marks and by how trainable a paper is. Descriptive and writing papers reward timed practice, so reserve hours for writing and for timed mocks, not only reading.
- Create tasks from the official syllabus sections, in a learning order that fits the calendar; interleave subjects so each paper advances.
- Add timed mock papers as `gate` tasks (3 h for a 3-hour paper), spaced so the learner gets feedback before the exam, plus a revision buffer.
- Keep a daily habit outside the targets when it matters (current affairs reading, vocabulary), and say so in the reply.
- Set the deadline a day before the exam (or the first paper). Compare required pace with the learner's hours; if infeasible, show trade-offs.

## 4. Record what you did
Put official and key sources in `sources`, the date you checked in `verifiedOn`, and every assumption in `notes`. Tell the learner to re-confirm dates on the official site near the exam, because tentative dates move.

## 5. If you cannot browse
Say so, build from what the user gives you, mark everything unverified in `notes`, and ask them to paste the syllabus or notice.
